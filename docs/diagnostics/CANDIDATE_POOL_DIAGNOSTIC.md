# V2.7候选池Oracle诊断

## 目的与口径

该诊断不修改V2.7。运行时保存每批全局和局部候选池；运行结束后，离线调用
真实CEC函数评价通过原距离筛选的候选。额外评价不计入300 FEs，也不反馈给
优化器，只用于回答两个问题：

1. 候选池是否生成了优于批次开始时真实incumbent的点；
2. V2.7实际选择的两个点是否捕获了这次改善机会。

可行性阶段按照初始固定约束尺度的真实标准化CV比较；目标阶段只把真实可行且
目标优于incumbent的候选计为改善。`true rank`始终遵循真实可行优先规则。

实验覆盖CEC2017 C01、C05、C22，10D/30D，seed 1--3，每次300 FEs。
开启候选池记录后的18个最终结果与已有V2.7相同seed结果逐项一致。

## 结论

### C01和C05：主要是候选排序瓶颈

C01/C05的目标阶段在95.8%--99.3%的批次都已经生成真实改善点。C01-30D
只捕获16.2%，C05-10D/30D只捕获26.5%/29.3%。因此继续扩大相同候选池
不会解决主要问题；下一步应只改V2.7目标阶段排序。

C01-10D是相对健康的对照：捕获67.4%，真实排名中位数4.0%。这也说明诊断
没有把“池子越大必然有oracle极值”误解释为所有场景都排序失败。

### C22-10D：阶段切换后可行性判错

可行性阶段的全局/局部预测CV与真实CV的Spearman中位数约0.964/0.995，整体
CV排序并不差；但真实可行候选极少，候选池平均只有0.28%可行，出现真实可行
候选时实际选中可行点的比例仅3.4%。

找到首个真实可行解后问题更明显：96.2%的目标阶段批次池内存在真实可行点，
实际两点保持可行的比例只有2.0%，改善捕获率仅2.6%。P90稳健可行判定对这些
真实可行候选的召回率为0，导致正常目标槽位全部落入连续CEI回退。此时主要
问题不是目标池生成，而是过于保守的可行门控和回退排序不能保持已发现的可行域。

### C22-30D：候选生成/可达性瓶颈

三个seed的405个批次中，距离筛选后的候选池没有出现一个真实可行点。V2.7
对真实CV改善机会的捕获率为69.8%，实际选中点真实排名中位数0.8%，说明现有
CV排序已经相当有效。单纯重排同一候选池不能解决C22-30D；需要改变候选生成、
约束边界搜索几何或评价预算。

## 使用方法

实验必须启用`--save-candidate-pools`，然后运行：

```powershell
python diagnose_candidate_pools.py <result-root>
```

输出包括逐槽位`oracle_slots.csv`、逐批次`oracle_batches.csv`和紧凑汇总
`oracle_summary.csv`。

这些oracle结果只能用于离线诊断，不能参与算法选点或作为正常FE内的性能结果。

## 简单选择器离线回放

在相同固定候选池和真实历史上进一步回放六种选择规则。最有价值的两个局部
替换规则都保留V2.7的P90主分支，只修改P90稳健可行候选不足时的回退：

- `P90 -> raw`：在原始预测可行候选中选择最小预测目标；
- `P90 -> probability`：选择经验联合可行概率最大的候选，概率相同时选择最小
  预测目标。

| Case | 当前P90捕获率 | P90 -> raw | P90 -> probability |
|---|---:|---:|---:|
| C01-10D | 67.4% | 68.9% | 67.7% |
| C01-30D | 16.2% | 15.9% | 18.7% |
| C05-10D | 26.5% | 28.7% | 30.1% |
| C05-30D | 29.3% | 38.4% | 31.3% |
| C22-10D | 2.6% | 5.3% | 7.9% |
| 汇总 | 34.62% | 37.35% | 36.75% |

`P90 -> raw`的汇总捕获率最高，但C01-30D有轻微退化，并在一个seed上下降。
`P90 -> probability`在所有场景汇总和逐seed比较中均未降低捕获率，可行候选
捕获率也由95.25%提高到96.55%。因此当前推荐后者作为下一次单因素实现：它
保留P90正常工作时的全部逻辑，只将连续CEI乘积回退替换为清楚的字典序规则，
不改变可行性阶段、候选生成、批次角色、种群淘汰或局部搜索。

离线回放只评估固定轨迹上的单步决策。它适合筛选规则，但不能代替新规则改变
后续样本和候选池后的完整300-FE闭环实验。

## V2.13闭环复核

上述`P90 -> probability`规则已作为V2.13完成5个配对seed的闭环实验。它在
C01-30D为0胜5负，在C05-30D为1胜4负，C22-10D成功率仍为4/5；C22-30D
因始终没有进入目标阶段而与V2.7完全相同。概率回退在C05中虽大多选到真实
可行点，却削弱了可行域内目标推进；在C01-30D中少量不同选点也改变了后续
代理和候选池轨迹。因此该结果明确说明：固定轨迹捕获率只能作为机制筛查指标，
不能直接视为闭环性能预估。V2.13不替代V2.7。
